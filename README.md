# 教学机

在浏览器里组装一台 RV32I 计算机，上电后从引导程序跑到自己的操作系统，并点开零件看这一拍到底在做什么。

指令集固定为 RV32I。换 CPU、内存或显卡，只改变容量、功耗和能不能接上，已经写好的程序仍然从同一地址启动。

## 页面

| 页面 | 做什么 |
| --- | --- |
| 组装 | 把主板、CPU、内存、显卡、电源、磁盘、显示器、键盘拖进机箱，并看功耗、容量和分辨率 |
| 上电 | 按顺序自检。功率不够、没有内存、显示器超过显卡输出时，会停在不同步骤 |
| 运行 | 单步或连续执行，看显示器、程序计数器和数据通路 |
| 原理 | 看主板上的连线、零件内部，以及操作系统怎样接管这些硬件 |
| 编程 | 写 RV32I 汇编，或载入仓库里的内核，写入虚拟磁盘 |

自检全部通过后会进入运行页。改过磁盘内容后，要回到上电页重新上电，引导程序才会装入新程序。

## 建议先走这一条

1. 在组装页点「推荐教学机」。
2. 到上电页按「上电」，再逐步「继续自检」。
3. 运行页应出现终端上的 `OK`。
4. 到编程页点「载入内核」，回到上电页重新上电。
5. 串口打印 `HI`。定时器中断会把 CPU 从用户线程抢走，两个线程轮流运行。
6. 在原理页点 CPU 的「详细」，单步到 `add`、`addi` 或 `sub` 时，能看到全加器这一拍的进位。减法是同一组加法器：B 按位取反，最低位进位为 1。

另外三套配置用来看失败：

- 功率不足：停在电源，不取指。
- 没有内存：停在内存检查。
- 分辨率过高：显示器高于显卡输出，上电失败。
- 内存过小：64 KiB 装不下内核，引导程序写 `MEM` 后停机。

## 机器规格

复位后的程序计数器指向引导 ROM。

| 地址 | 内容 |
| --- | --- |
| `0x00000000` | 引导 ROM，4 KiB，只读 |
| `0x10000000` | 定时器 |
| `0x10001000` | 串口 / 字符终端 |
| `0x10002000` | 键盘扫描码 |
| `0x10003000` | 机器信息：内存容量、帧缓冲宽高 |
| `0x10010000` | 显存，长度由显卡决定 |
| `0x40000000` | 磁盘窗口，只读 |
| `0x80000000` | 内存。内核装在这里，长度由内存条决定 |

引导程序只做三件事：检查内存可写、把磁盘程序抄到 `0x80000000`、跳过去。磁盘开头 16 字节是魔数 `0x54454348`、装入地址和长度。

仿真每次接受整机状态和一个时钟，返回新状态。画面只读这个状态。

## 操作系统

网页里实际启动的内核是 [`src/firmware/kernel.S`](src/firmware/kernel.S)。它会：

1. 设置栈，写入 `mtvec` 和 `mscratch`。
2. 用 `ecall` 把字符写到串口。
3. 打开定时器，`mret` 进入用户态。
4. 中断时把寄存器存进线程控制块，换一个线程再恢复。

[`os/kernel.c`](os/kernel.c) 和 [`os/start.S`](os/start.S) 是同一条启动线的 C 与汇编，链接地址也是 `0x80000000`。本机装有 `riscv32-unknown-elf-gcc` 时，在 `os/` 里执行 `make`。网页不内置 C 编译器。

缺页演示会打开一个最小 Sv32 页表。访问未映射地址时，机器停在那一拍，原理页能看到失败的页表项。
